# Glossary

Technical terms and acronyms used throughout the Physical AI & Humanoid Robotics Course.

## A

**ABET** - Accreditation Board for Engineering and Technology. Organization that accredits engineering and technology programs in the United States.

**Action Space** - The set of all possible actions a robot can take in response to a given state or command.

**Autonomous Navigation** - The capability of a robot to move through an environment without human intervention, using sensors and planning algorithms.

## B

**Behavior Tree** - A hierarchical structure used in robotics for decision-making and task execution, commonly used in the ROS 2 Nav2 stack.

**BibTeX** - A reference management format used for citations and bibliographies in academic writing.

## C

**Capstone Project** - An integrative final project that demonstrates student mastery across all four course modules.

**Costmap** - A grid-based representation of the environment used for navigation planning, indicating obstacle locations and traversability.

## D

**Docker** - A containerization platform used to create isolated, reproducible test environments for code examples.

**Docusaurus** - An open-source static site generator used to build this course documentation.

**Domain Randomization** - A technique in sim-to-real transfer where training environments are varied to improve policy generalization to real-world conditions.

## E

**Edge AI** - Artificial intelligence computation performed on local devices (e.g., NVIDIA Jetson Orin) rather than in the cloud.

## F

**Frontmatter** - YAML metadata at the top of Markdown files (e.g., `id`, `title`, `sidebar_position`) used by Docusaurus for page configuration.

## G

**Gazebo** - An open-source robot simulation platform supporting physics simulation, sensor models, and ROS integration.

**GitHub Pages** - A static site hosting service integrated with GitHub repositories, used to deploy this documentation.

**Grasp Planning** - The process of computing optimal hand/gripper configurations and approach trajectories for object manipulation.

## H

**Humanoid Robot** - A robot with a body shape resembling the human form, typically including head, torso, arms, and legs. Examples: Unitree H1, Figure 01, Boston Dynamics Atlas.

## I

**Isaac Sim** - NVIDIA's robot simulation platform built on Omniverse, designed for synthetic data generation and AI training.

## J

**Jetson Orin** - NVIDIA's edge AI computing platform for robotics, providing GPU acceleration for perception and control algorithms.

## K

**Kinematics** - The study of motion without considering forces, fundamental to robot arm control and path planning.

## L

**Lab Tier** - One of three infrastructure configurations for Physical AI labs: Proxy (simulation-only), Miniature (compact robots), Premium (full-scale robots).

**LiDAR** - Light Detection and Ranging. A sensor that uses laser pulses to measure distances and create 3D maps of the environment.

## M

**MDX** - Markdown with JSX (React components), allowing interactive elements in Markdown documentation.

**Miniature Tier** - Lab infrastructure configuration with GPU workstations and 1-2 compact humanoid robots ($50-70K).

**Multimodal Learning** - AI systems that process multiple input types (e.g., vision, language, proprioception) simultaneously.

## N

**Nav2** - ROS 2 Navigation Stack, providing autonomous navigation capabilities including path planning, obstacle avoidance, and behavior coordination.

**Node** - In ROS 2, an independent process that performs computation and communicates with other nodes via topics, services, or actions.

## O

**Omniverse** - NVIDIA's platform for 3D simulation and collaboration, foundation for Isaac Sim.

**On-Premise** - Infrastructure deployed and maintained locally at the institution, as opposed to cloud-based solutions.

**OpenVLA** - An open-source vision-language-action model for robotic manipulation tasks.

## P

**Physical AI** - Artificial intelligence systems that interact with and manipulate the physical world, typically through robotics.

**Premium Tier** - Lab infrastructure configuration with extensive GPU workstations and 3-5 full-scale humanoid robots ($120-180K).

**Proxy Tier** - Lab infrastructure configuration with simulation-only workstations, no physical robots ($10-20K).

**Publisher** - In ROS 2, a node that sends messages to a topic.

## Q

**Quality Gate** - A validation checkpoint that must pass before proceeding (e.g., all code examples tested, word count verified, build successful).

## R

**Reality Gap** - The difference between simulated and real-world environments that can cause policies trained in simulation to fail on physical robots.

**ROS 2** - Robot Operating System 2, a middleware framework for robot software development providing communication, device drivers, and tools.

**RT-1** - Robotics Transformer 1, a vision-language-action model developed by Google for robotic manipulation.

**RT-2** - Robotics Transformer 2, an improved VLA model that transfers web knowledge to robotic control.

## S

**SDF** - Simulation Description Format, an XML format for robot and environment models in Gazebo.

**Service** - In ROS 2, a request-response communication pattern between nodes.

**Sim-to-Real Transfer** - The process of applying policies or models trained in simulation to physical robots.

**Subscriber** - In ROS 2, a node that receives messages from a topic.

**Synthetic Data** - Artificially generated training data created in simulation rather than captured from real-world sensors.

## T

**Topic** - In ROS 2, a named channel for asynchronous message passing between nodes.

**Transformer** - A deep learning architecture based on self-attention mechanisms, foundational for vision-language models.

## U

**Unity** - A game engine and development platform with robotics extensions, used for high-fidelity robot visualization.

**Unitree** - Chinese robotics company producing compact humanoid robots (H1, G1) and quadrupeds used in education and research.

**URDF** - Unified Robot Description Format, an XML format for representing robot models in ROS.

## V

**VLA** - Vision-Language-Action. Multimodal AI models that process visual input and natural language commands to generate robot actions.

**Vision-Language Model** - AI systems that understand both images and text, enabling natural language interaction with visual data.

## W

**Workspace** - In ROS 2, a directory containing source code, build files, and installation for ROS packages.
